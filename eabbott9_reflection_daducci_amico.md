### Inactivity patterns
Honestly, this project never really went inactive. Sure, there were a couple of small gaps throughout its lifespan, but it's had spikes of commits around the same size every 3-4 months. For these gaps, one developer would start it by releasing a new version. Another developer would recover the project from the gap by merging other pull requests. Perhaps activity was maintained by distributing the responsibility of the project and picking a large project.

### Was the longest gap was easy/hard to interpret?
Since there are so many small gaps in this project, its hard to guess why any one gap occured. However, at a bird's eye view it feels easy to think that all of the gaps were just times between new releases.

### Likely reasons for inactivity and recovery
Inactivity:
    - Developers were working on new versions of the project.
Recovery:
    - A different developer from the last version release would merge a new release branch into main.
